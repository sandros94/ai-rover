# Vision (narrative)

> Story form, for shared understanding. The dependency-ordered build plan is `docs/plan.md`. When the two drift, investigate before resolving.

A rover the size and weight of Perseverance sits on procedurally generated Martian terrain. Nobody drives it. The community decides where it goes next: while the rover is already rolling from one checkpoint to the next, signed-in users click a _destination_ on the map for the segment after that, within 50–250 m of the planned stop and only on ground the rover has actually seen, and everyone can like the submissions they prefer. When the current segment ends, the most-liked submission wins (ties broken by confidence weights computed when the submission was validated), the server plans the drive, and the rover sets off again. Because a real rover moves at a walking-snail's pace (152 m/h at the cap, 200–300 m per sol in practice), a segment takes long enough that people can check in a few times a day and see the story advance. That slowness is a feature: it is the project's natural rate limit.

The AI part is deliberately narrow. TypeSafe's Jev is a _judgment_ model, not a text generator: it returns typed answers (a choice, a yes-probability, a level) over state that code hands it. So code owns the terrain, the path planner and the physics; Jev answers questions code cannot answer with arithmetic: "is this destination reasonable for this rover on this terrain", "how much should we trust the computed distance and time", "which of these candidate routes is the sane one". Every submission costs a fraction of a cent, and the winning route is the only one that gets fully simulated.

Driving can fail: a slope too steep, a rock too tall, a sand trap. The failure is detected by the simulation (and, as a fallback, by a community vote when the rover visibly is not moving). A safe stop short of the goal is not a failure: it becomes a checkpoint and the next round starts from there. A real failure resets the rover to the checkpoint that started the failed segment; three failures near the same spot push it back one more checkpoint. Every attempt, successful or not, is journaled: past segments draw the trail, failed ones leave a red ghost and a red circle, and anyone can replay the whole journey or a slice of it locally without touching live state. A mission clock counts sols since landing.

Hosting is Netlify: Postgres for the live relational state (users, submissions, votes, segment lifecycle), Blobs behind the CDN for the immutable journal (one file per segment attempt: the plan, the keyframes, the outcome). Netlify has no server-side WebSockets, so browsers play the precomputed keyframes back locally against wall-clock and poll a small CDN-cached mission-state endpoint for the rest.
